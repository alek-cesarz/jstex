# Design — jstex: STEX-light explorer for JupyterLab

**Date:** 2026-09-29
**Status:** approved 2026-09-29 (amended by plan verification, see §12)
**Repo:** `alek-cesarz/jstex` — this spec moved here from the STEX repo on 2026-10-05.

---

## 1. Purpose and scope

jstex brings a stripped-down STEX into JupyterLab so notebook users can **find
STAC items on a map and get them into their code** without copy-typing: item
links, attribute values, asset hrefs, and — optionally — ready-to-use S3
access for those assets.

**Users.** Primarily Python users on a new JupyterHub deployment. Every user is
logged in via OIDC (Keycloak), so an access token is always available. R and
Julia are supported only where the implementation is shared with Python (§9,
stage 3).

**In scope**

- 2D map with AOI drawing, collection + date (+ later attribute) search,
  results list, item details.
- Access to **restricted STAC collections** using the user's OIDC token.
- Python access to results as `pystac` objects.
- Copy actions for item self link, id, property values, asset hrefs, links.
- Opt-in S3 key management so search results can be passed straight to
  boto3 / fsspec / GDAL (§6).
- Two front doors on one UI: an in-cell widget (stages 1–2) and a JupyterLab
  panel (stage 3).

**Not in scope** — workspace, downloads/download manager, visualization
(COG/JP2/WMS), processing/orders, login UI, i18n (English only in v1).

## 2. Decisions (with rationale)

| # | Decision | Why |
|---|---|---|
| D1 | **Own private repo, one pip package `jstex`**, packaged like other JupyterLab extensions (hatchling + `hatch-jupyter-builder`, prebuilt labextension inside the wheel). | User requirement; no `jupyter lab build` for users. |
| D2 | **Staged delivery: widget first, panel later.** | User requirement: start barebones, expand. |
| D3 | **In-cell widget uses anywidget.** | Works in JupyterLab, Notebook 7, VS Code, Colab; plain ESM bundle buildable with Vite; Python-synced state. |
| D4 | **All STAC traffic and all secrets live in Python** (kernel for the widget, jupyter-server extension for the panel); the browser is a thin view. | Token and S3 keys never reach browser JS; results are native `pystac` objects; the panel reuses the same Python module; R/Julia snippet insertion rides on it. Trade-off accepted: the widget is unresponsive while another cell runs. |
| D5 | **Code shared with STEX is copied, not packaged.** Only small pure modules (`antimeridian.ts`, date/format helpers, the property-group data) are copied, each with a provenance header naming the STEX source file and commit. | STEX's search stack is coupled to its global store, config, i18n and `map-view`; with D4, the TS overlap shrinks to a few hundred lines. Extracting `@stex/core` is not justified yet. |
| D6 | **Config = kwargs → `JSTEX_*` env vars → CDSE defaults.** The provider is a single class, not a plugin interface. | Target deployment has its own STAC/keys-manager/S3 URLs on CDSE-style infrastructure; no second platform exists yet (YAGNI). |
| D7 | **QueryState wire format is identical to STEX's `?q=`** (base64url of UTF-8 JSON, `aois:[{g,s}]`, legacy `aoi`, defaults omitted). | Free two-way hand-off: "Open in STEX" and `Explorer(q=<STEX share URL>)`. |
| D8 | **Vertical layout** in the cell: query bar → map → results → details. | Notebook output scrolls; vertical avoids cramming side panels. |
| D9 | **Private distribution**: CI builds the wheel and attaches it to a GitHub Release; the hub single-user image installs it with a read-only token passed as a Docker build secret. `Private :: Do Not Upload` classifier. No license file (all rights reserved). | Private repo, private package, no specific license. A prebuilt wheel avoids Node in the hub image. |

## 3. Deployment prerequisites (JupyterHub + OIDC)

Verified against JupyterHub 6.0.1, OAuthenticator 17.4.0, z2jh chart 4.4.2
(docs + source, 2026-09).

1. **Authenticator:** `GenericOAuthenticator` against Keycloak. No discovery
   support — set `authorize_url`, `token_url`, `userdata_url` explicitly.
2. **`auth_state`:** `Authenticator.enable_auth_state = true` must be set
   explicitly in z2jh (`hub.config.Authenticator.enable_auth_state`); the crypt
   key is auto-generated by the chart. auth_state contains `access_token`,
   `refresh_token`, `id_token`, `scope`, `token_response`, `oauth_user`.
3. **RBAC** so the single-user server can read its own auth_state live:

   ```python
   c.JupyterHub.load_roles = [
     {"name": "user",   "scopes": ["self", "admin:auth_state!user"]},
     {"name": "server", "scopes": ["users:activity!user", "access:servers!server",
                                    "admin:auth_state!user"]},
   ]
   ```

   User servers must be restarted after this changes.
4. **Endpoint:** read via `GET $JUPYTERHUB_API_URL/users/$JUPYTERHUB_USER`.
   `GET /hub/api/user` (as the OAuthenticator refresh how-to suggests) returns
   `auth_state: null` — jupyterhub/jupyterhub#5103.
5. **Refresh:** OAuthenticator ≥ 17.2 refreshes via the refresh token when the
   hub handles an authenticated request (including the server's API calls),
   at most every `auth_refresh_age` (default 300 s), and only when the userinfo
   check fails — it does not look at `exp`. Set `auth_refresh_age` to 30–60 s
   and add an `exp`-aware `refresh_user_hook` (≥ 17.3). Do not use
   `userdata_from_id_token=True` (it disables effective refresh).
6. **Env for jstex** via `singleuser.extraEnv`: `JSTEX_STAC_URL`,
   `JSTEX_S3_KEYS_URL`, `JSTEX_S3_ENDPOINT`, `JSTEX_S3_ENABLED`.

All of the above ships as `deploy/z2jh-values.example.yaml` in the jstex repo.
The refresh hook is a sketch until tested on the target hub (§11).

**Security notes.** User code can always read the token (the server's API
token is inherited by kernels). jstex never exposes the refresh token. The
stage 3 server endpoint returns only `{access_token, expires_at}`, requires
Jupyter server auth, is GET-only, sends `Cache-Control: no-store`, and has no
CORS. With JupyterHub server sharing, anyone the server is shared with can reach
that endpoint — documented, not mitigated.

## 4. Architecture

```
jstex/
├─ pyproject.toml                  # hatchling + hatch-jupyter-builder; Private :: Do Not Upload
├─ src/jstex/
│  ├─ __init__.py                  # Explorer, item(), search()
│  ├─ config.py                    # kwargs → JSTEX_* env → CDSE defaults
│  ├─ auth.py                      # token provider chain (§5.2)
│  ├─ stac.py                      # pystac-client wrapper, stateless (§5.3)
│  ├─ query.py                     # QueryState + STEX-compatible codec (§5.4)
│  ├─ widget.py                    # anywidget Explorer                  (stage 1)
│  ├─ s3.py                        # S3 key management + helpers         (stage 2)
│  ├─ server/                      # jupyter-server extension /jstex/api  (stage 3)
│  └─ static/                      # built JS bundles
├─ js/                             # TypeScript frontend
│  ├─ widget.ts                    # anywidget render(); CommBackend
│  ├─ panel.ts                     # JupyterLab plugin; RestBackend       (stage 3)
│  ├─ backend.ts                   # Backend interface
│  ├─ state.ts                     # per-instance store
│  ├─ strings.ts                   # all UI strings (English)
│  └─ ui/{query-bar,map,results,details}.ts
├─ deploy/z2jh-values.example.yaml
├─ tests/                          # pytest, vitest, Galata
├─ README.md  DEVELOPMENT.md  CHANGELOG.md
```

Scaffolded from the official `copier` **jupyterlab/extension-template**
(frontend-and-server) in stage 1, so CI, packaging and Galata match other
JupyterLab extensions from day one. The anywidget ESM bundle is a second,
Vite-built target; the labextension plugin is a stub until stage 3. The
labextension package name is `@jstex/labextension` (the unscoped npm name
`jstex` is taken; jstex is never published to npm).

**Data flow.** UI views talk only to the `Backend` interface:

```ts
interface Backend {
  listCollections(): Promise<CollectionSummary[]>;
  queryables(collectionId: string): Promise<QueryablesSchema>;
  search(state: QueryState): Promise<Page>;       // Page = { items, nextLink? }
  nextPage(nextLink: StacLink): Promise<Page>;
  cancel(): void;
}
```

- `CommBackend` (widget): anywidget custom messages to the kernel, correlated
  by `req_id`.
- `RestBackend` (panel, stage 3): `ServerConnection.makeRequest` to
  `/jstex/api/*`, which calls the same `stac.py`/`auth.py`.

## 5. Python backend

### 5.1 `config.py`

Resolution: explicit kwargs → env vars → defaults.

| Setting | Env | Default |
|---|---|---|
| STAC URL | `JSTEX_STAC_URL` | `https://stac.opensearch.dataspace.copernicus.eu/v1/` |
| S3 keys manager | `JSTEX_S3_KEYS_URL` | `https://s3-keys-manager.cloudferro.com/api/user` |
| S3 endpoint | `JSTEX_S3_ENDPOINT` | `https://eodata.dataspace.copernicus.eu` |
| S3 enabled | `JSTEX_S3_ENABLED` | off |
| Dev token | `JSTEX_ACCESS_TOKEN` | — |
| STEX base URL (for share links) | `JSTEX_STEX_URL` | unset |

### 5.2 `auth.py`

Provider chain, first hit wins:

1. **Hub** — when `JUPYTERHUB_API_TOKEN`, `JUPYTERHUB_API_URL`,
   `JUPYTERHUB_USER` are set: `GET {api}/users/{user}` with
   `Authorization: token …`; take `auth_state.access_token`. Read `exp` from
   the JWT payload (decode only, no signature verification needed for
   caching). Cache until `exp − 60 s`. If `auth_state` is `null`, warn once
   pointing at `deploy/z2jh-values.example.yaml` and fall through.
2. **Env** — `JSTEX_ACCESS_TOKEN`.
3. **Anonymous.**

Public: `jstex.auth.get_token(force_refresh=False) -> str | None`,
`jstex.auth.headers() -> dict`. Thread-safe (lock). Never returns or logs the
refresh token.

### 5.3 `stac.py`

- `pystac_client.Client.open(url, modifier=…)`; the request modifier injects a
  fresh `Authorization: Bearer` header on every request.
- On 401: `get_token(force_refresh=True)`, retry once.
- On 429: bounded exponential backoff (same policy as STEX).
- `list_collections() -> list[CollectionSummary]` (`id`, `title`, `extent`) —
  whatever the token can see, which is how restricted collections appear.
- `queryables(collection_id)` — cached per collection per process.
- `search_page(state) -> Page(items, next_link)`.
- `next_page(next_link) -> Page` — follows the `rel=next` link **exactly**,
  including `method`, `body`, `merge` when present, via pystac-client's
  `StacApiIO`. No iterator is held, so the stage 3 REST server can round-trip
  `next_link` through the browser.
- Callers deduplicate by item `id` on append.
- The default endpoint requires at least one collection per search; the UI
  keeps Search disabled until one is selected.

### 5.4 `query.py`

- `QueryState` dataclass: `collections`, `datetime {from,to}`, `aois
  [{geometry, selected}]`, `filters [{field, op, value}]`, `sort`,
  `page_size` (default 50).
- `encode(state) -> str` / `decode(q: str) -> QueryState` — byte-compatible
  with STEX `src/lib/query-codec.ts` (base64url UTF-8 JSON; compact
  `aois:[{g,s}]`; legacy single `aoi`; defaults omitted; coordinates rounded as
  STEX does). `decode` also accepts a full STEX share URL and extracts `q`.
  Invalid input raises `JstexQueryError("Invalid query URL")`.
- `to_search_params(state)`:
  - `collections`;
  - `datetime` as `"from/to"` **only when both are set**;
  - `intersects` from selected AOIs — one geometry as is; several as one
    `MultiPolygon` after `shapely.unary_union` (avoids CDSE `GEOSIntersects:
    TopologyException` on overlapping pieces; stage 2, since stage 1 has a
    single rectangle);
  - `limit` from `page_size`;
  - `filter` + `filter_lang="cql2-json"` — port of STEX `cql2.ts`: one
    predicate → `{op, args:[{property}, value]}`, several → wrapped in
    `{op:"and"}`.

### 5.5 `widget.py` — `jstex.Explorer(q=None, stac_url=None, height=450)`

- **Synced traitlets:** `query` (QueryState dict), `selected_ids`,
  `active_id`, `status` (`idle`|`searching`|`error`), `error`.
- **Python-only accessors** (built from loaded items, never synced as traits):
  - `ex.results` → `pystac.ItemCollection` of all loaded items;
  - `ex.selected_items` → `list[pystac.Item]`;
  - `ex.selected_item` → the active `pystac.Item` or `None`;
  - `ex.query_url()` → STEX share URL (`$JSTEX_STEX_URL?q=…`) for the current
    query; returns just the encoded `q` when `JSTEX_STEX_URL` is unset.
- **Methods:** `ex.search()`, `ex.load_more()`; assigning `ex.query = …`
  updates the UI.
- **Messages** JS→Py: `collections`, `queryables`, `search`, `next`, `cancel`,
  each with `req_id`. Py→JS replies are **custom messages**, not traitlets,
  because a page of CDSE items can be several MB and must not be re-sent on
  every sync.
- **Concurrency:** searches run on a worker thread so the handler returns
  immediately and `cancel` is processed. Cancel bumps a generation counter;
  stale replies are dropped; previous results stay intact. Stage 1 spike
  (§11): confirm sending anywidget messages from a worker thread is reliable on
  current ipykernel; if not, run search synchronously in the handler and ship
  stage 1 without Cancel.
- **Known limitation:** while another cell is executing, widget messages
  queue behind it. Documented; the stage 3 panel does not have this issue.

Convenience: `jstex.item(href) -> pystac.Item` (`Item.from_file` with auth
headers) and `jstex.search(q_or_state) -> ItemCollection` (headless replay).

### 5.6 Errors

Typed exceptions: `JstexAuthError`, `JstexStacError`, `JstexQueryError`,
`JstexS3Error`. The widget renders them as a dismissible, non-blocking banner
with Retry.

## 6. S3 key management (stage 2, opt-in)

**Enablement:** `pip install jstex[s3]` (adds `boto3`, `filelock`) **and**
`JSTEX_S3_ENABLED=1`. Otherwise `jstex.s3.*` raises `JstexS3Error` explaining
how to enable it.

**Lifecycle** — ported from STEX `src/lib/platforms/cdse.ts` and
`src/lib/s3-credentials.ts`; the keys-manager request/response shapes are
taken from `cdse.ts`, not re-derived.

- **Mint** via the keys-manager API with the Bearer token from `auth.py`.
- **Shared cache across kernels:** `~/.config/jstex/s3-credentials.json`, mode
  `0600`, keyed by keys-manager URL + hash of the token `sub`. A `filelock`
  guards mint/rotate so concurrent kernels produce one key.
- **Rotate** when < 1 h of validity remains; delete the superseded key jstex
  minted, so jstex holds at most one slot of the per-user key cap.
- **Invalidate** on `403 InvalidAccessKeyId`: drop, re-mint once, retry.
- **Propagation wait** after minting: signed `ListObjectsV2 max-keys=1
  delimiter=/` on the bucket root, reading the S3 error *code*; never a
  specific object.
- **Key cap reached:** `JstexS3Error("S3 key limit reached — remove unused keys
  at <manager UI>")`, negative-cached for 30 s.

**API**

```python
jstex.s3.client(asset=None)         # boto3 S3 client; endpoint from asset storage:schemes or default
jstex.s3.location(asset_or_href)    # {"Bucket": …, "Key": …} from s3:// href or alternate.s3
jstex.s3.session()                  # boto3.Session
jstex.s3.storage_options()          # fsspec / s3fs / xarray
jstex.s3.gdal_env()                 # rasterio.Env / GDAL /vsis3/
jstex.s3.write_aws_profile("jstex") # opt-in: ~/.aws/credentials + config (endpoint_url)
```

- Credentials are `botocore` `RefreshableCredentials` backed by the file
  cache, so long-lived clients survive rotation.
- Endpoint per asset from `storage:schemes` (port of STEX
  `resolveS3EndpointForAsset`).
- Path-style addressing, matching what STEX signs today (verify against
  `eodata` in stage 2).
- Typical use: `jstex.s3.client(asset=a).download_file(**jstex.s3.location(a),
  Filename=…)`.

## 7. Frontend

### 7.1 Layout (vertical, full cell width)

```
┌───────────────────────────────────────────────────────────┐
│ Query bar: [Collections ▾] [From] [To] AOI: bbox·km² ✕ [Search] │
├───────────────────────────────────────────────────────────┤
│ Map — full width, 450 px default, drag-resizable          │
├───────────────────────────────────────────────────────────┤
│ Results  12 loaded · 3 selected           [Load more]     │
│ table, own scroll (max ≈250 px), sticky header            │
├───────────────────────────────────────────────────────────┤
│ Item details  ◀ Prev  3 / 12  Next ▶                      │
│ header + copy actions · Properties · Assets · Links       │
│ full height, scrolls with the notebook                    │
└───────────────────────────────────────────────────────────┘
```

- **Query bar:** wraps on narrow cells; stage 2 adds a "Filters (n)" disclosure
  beneath it. Collection picker is searchable by id/title.
- **Map:** `eox-map` + `eox-drawtools` (rectangle in stage 1; polygon in
  stage 2). Basemaps as in STEX: CartoDB Voyager (light), Stadia Alidade Smooth
  Dark (dark). Footprints for loaded items only; antimeridian split via copied
  STEX `antimeridian.ts`.
- **Results table:** checkbox, shortened id, datetime, collection; `cloud %`
  column only when items carry `eo:cloud_cover`.
- **Item details:** Properties collapsed by default; Assets and Links expanded.

### 7.2 Behaviour

- Row click → highlight footprint, show details.
- Footprint click → select row, scroll it into view **inside the table only**
  (never moves the notebook), show details.
- Prev/Next → next/previous loaded item, map highlight follows.
- Checkboxes → `selected_ids`; details → `active_id`; both sync to Python
  immediately.
- Search disabled until ≥ 1 collection is selected. With a collection but no
  AOI/date, Search is allowed with a warning (default endpoint needs a
  collection; `page_size` caps the result).
- Load more appends without clearing selection; dedup by id.

### 7.3 Copy targets (the core value)

- Header: item **self link**, **item id**, **Python snippet**
  `jstex.item("<self href>")`.
- Properties: key/value table (flat and sorted in stage 1; grouped
  General/Product/Acquisition/Geometry/Storage in stage 2 using STEX
  `sensor-config.ts` groups ported to a JSON data file), copy per value.
- Assets: key, title, media type, roles, href (+ S3 alternate when present
  via `alternate.s3` / `storage:schemes`), copy per href; stage 2 adds
  "copy boto3 snippet" per asset.
- Links: `rel`, `href`, copy.
- Hint line: "`ex.selected_item` holds this item in Python."
- Clipboard: `navigator.clipboard`, falling back to hidden-textarea
  `execCommand('copy')` outside secure contexts; short "Copied" toast.

### 7.4 Implementation rules

- Per-instance store created in each `render()`; no module-level state, so two
  explorers in one notebook are independent.
- Each view is `(el, store, backend)` and knows nothing about the other views.
- Custom elements registered with a guard (`customElements.get(tag) ??
  define(...)`).
- All CSS scoped under a `.jstex` root; colours from `--jp-*` variables with
  fallbacks for VS Code/Colab; light/dark from `body[data-jp-theme-light]`;
  `--jstex-accent` carries STEX orange.
- Native HTML controls in stage 1 (no Shoelace).
- All UI strings in `strings.ts` (English).
- Copied STEX files carry a provenance header (source path + commit).

## 8. Stage 3 — JupyterLab panel

- jupyter-server extension under `/jstex/api/`: `collections`, `queryables/{id}`,
  `search`, `next`, `token` (returns only `{access_token, expires_at}`).
  Handlers subclass `jupyter_server.base.handlers.APIHandler` with
  `@tornado.web.authenticated`.
- Lab plugin: a command + launcher/sidebar entry opening the same UI in a
  main-area panel, wired to `RestBackend`. Unaffected by busy kernels.
- **"Insert snippet into active cell"** for the selected item/assets, with a
  template per kernel language (Python, R, Julia) chosen from the active
  notebook's kernelspec. Templates are data files sharing one placeholder
  schema — this is the only R/Julia surface.
- `jstex.s3.write_aws_profile()` exposed as a panel action, giving R
  (`paws`/`aws.s3`) and Julia (`AWS.jl`) S3 access with no jstex-specific code.

## 9. Stages and acceptance criteria

### Stage 1 — barebones widget → `v0.1.0`

- `jstex.Explorer()` renders map, query bar, results, details.
- Collections list reflects token visibility: a restricted collection
  appears when the hub token grants it and not when anonymous (mocked in
  tests).
- Draw rectangle → AOI summary shows bbox + approx area; Clear removes it.
- Search sends `intersects` only when an AOI is set, `datetime` only when both
  dates are set.
- Results render; row↔footprint selection sync; Prev/Next.
- `ex.selected_item` is a `pystac.Item` equal to the item shown; its
  `self_href` equals the copied self link.
- Copy buttons for self link, id, property values, asset hrefs, links.
- Expired cached token → transparent refresh + one retry on 401.
- `auth_state: null` → one clear warning, anonymous fallback.
- Two explorers in one notebook do not interfere.

### Stage 2 — complete widget → `v0.2.0`

- Queryables-driven filter builder with type-aware operators; invalid
  operator/type blocks the search with a message; CQL2-JSON as in §5.4.
- Load more follows `rel=next` exactly and appends without duplicates or
  losing selection.
- Polygon draw; GeoJSON AOI upload with STEX validation rules (Polygon/
  MultiPolygon only; non-EPSG:4326 CRS rejected with "Only EPSG:4326 (WGS84
  lon/lat) supported."; multiple polygons → one MultiPolygon).
- Grouped properties; "copy boto3 snippet" per asset.
- `Explorer(q=<STEX share URL>)` restores state and auto-searches;
  `ex.query_url()` opens the same search in STEX; invalid `q` shows "Invalid
  query URL" without crashing.
- `jstex.s3.*` per §6, including concurrent kernels minting one key.

### Stage 3 — JupyterLab panel → `v0.3.0`

- Panel opens from launcher/command palette and searches while a notebook
  kernel is busy.
- Snippet insertion produces runnable code for Python; R and Julia templates
  produce code that reads item/asset URLs (and S3 via the AWS profile).
- `/jstex/api/token` requires server auth, is GET-only, `no-store`, and
  returns no refresh token.

Each stage is tagged (`vX.Y.0`) and recorded as a `MILESTONE:` commit.

## 10. Testing, CI, release

| Layer | Tooling | Covers |
|---|---|---|
| Python unit | pytest + `responses` | QueryState codec incl. **golden fixtures encoded by STEX's TS codec** (both directions); CQL2 mapping; auth chain (mock hub API, `null` auth_state, exp cache); 401 retry; 429 backoff; next-link following + dedup |
| S3 | pytest + `moto` server (custom endpoint) + mocked keys manager | mint, cross-process file lock, rotate + delete old key, 403 invalidate, key-cap error |
| Frontend unit | vitest | per-instance store; `req_id` correlation; stale reply after cancel dropped |
| E2E | Galata | notebook runs `Explorer()`, draws AOI, searches, `ex.selected_item` matches the details view |

E2E runs against a small local **fake STAC server** (`JSTEX_STAC_URL`) for
determinism. A manual smoke checklist covers the real hub (restricted
collection visible, token refresh after expiry, S3 read of one asset).

**CI** (GitHub Actions, from the template): ruff, prettier + eslint, pytest,
vitest, Galata, wheel build, `check-release`. **Release:** tag → CI builds the
wheel and attaches it to a GitHub Release (D9).

**Docs:** `README.md` (install into hub image, quick start, hub
prerequisites), `DEVELOPMENT.md` (architecture, setup, testing),
`CHANGELOG.md` (Keep a Changelog), `deploy/z2jh-values.example.yaml`.

**Versions at design time:** JupyterLab 4.6.4, jupyter-server 2.21.1,

## 12. Amendments from plan verification (2026-09-29)

Found while writing and live-testing the stage 1 plan
(`docs/superpowers/plans/2026-09-29-jstex-stage1.md`); they override the
sections named.

- **§5.3 — auth hook name.** Per-request token injection uses
  `StacApiIO(request_modifier=…)`. `modifier=` on `Client.open` modifies STAC
  objects, not HTTP requests.
- **§4 — repo layout.** Follows the JupyterLab extension template: Python
  package `jstex/` at the repo root, labextension TypeScript in `src/`, widget
  TypeScript in `js/` (own tsconfig, excluded from the template ESLint).
- **§7.1, §5.1 — basemap (user decision 2026-09-30).** Same providers,
  defaults and rules as STEX (Carto Voyager light, Stadia Alidade Smooth Dark;
  `{r}` → `@2x`; optional API key appended as `?<param>=<key>`), configurable
  per deployment via `JSTEX_BASEMAP_{LIGHT,DARK}_{URL,KEY,KEY_PARAM,ATTRIBUTION}`.
  Both need a key or a registered domain (else watermark tiles); the user
  provides keys / registers the hub domain.
- **§4, §5.5 — backend interface.** Search is push-based
  (`search(query)` + `{"type":"page"}` messages) so searches started from
  Python render too. New message `{"type":"sync"}`: every rendered view asks
  Python to re-send the current page (re-rendered outputs are not empty while
  the kernel holds results).
- **§7.4 — element registration.** anywidget re-evaluates the bundle for every
  new widget model, and the bundled `@eox/*` modules call
  `customElements.define` at load time. `js/define-guard.ts` (first import) makes
  re-definition a no-op; a `customElements.get()` check before a dynamic
  `import()` is not enough because Rollup inlines and evaluates it eagerly.
- **§11 — bundle size.** The single-file bundle is ~4.3 MB (1.1 MB gzip) and
  is sent for each `Explorer()`. It is acceptable for stage 1; stage 2 should
  serve it from the server extension or trim `@eox/map` dependencies.
- **§3 — refresh hook.** The custom `exp`-aware `refresh_user_hook` is not
  needed for stage 1. jstex retries a 401 after re-reading the hub, and that
  hub request triggers OAuthenticator's own refresh (at most every
  `auth_refresh_age`, set to 45 s in the example). The z2jh example ships
  without a hook.
- **§5.5 — `Explorer.search(wait=True)`** was added so `ex.search()` followed by
  `ex.results` works in a single cell.
- **§5.4, §7 — open-ended dates (user decision 2026-09-30).** Either end of the
  date range may be empty. Requests always carry a closed interval: a missing
  start becomes `1900-01-01T00:00:00Z`, a missing end `2099-12-31T23:59:59Z`.
  Reason: the CDSE endpoint accepts `from/..` but its firewall rejects
  `../to` ("Request Rejected").
- **§7.4 — light/dark mode (user requirement 2026-09-30).** The widget follows
  the host theme live (JupyterLab `body[data-jp-theme-light]`, VS Code
  `body.vscode-dark`, Colab `html[theme]`, else OS), exposes it as
  `data-theme` on the root, and switches the basemap with it.
- **§7.4 — i18n (user requirement 2026-09-30).** "English only" becomes
  "English first, translation-ready per the JupyterLab standard": gettext
  domain `jstex`, strings as literal `trans.__()` calls extracted by
  `jupyterlab-translate`, translations shipped in the wheel under
  `jstex/locale/<ll_CC>/LC_MESSAGES/jstex.{po,json,mo}` via the
  `jupyterlab.locale` entry point. The labextension plugin publishes
  `translator.load('jstex')` for the widget (which cannot request
  `ITranslator`); English fallback elsewhere. Verified end to end with
  `jupyterlab-language-pack-de-DE`.
- **Repo and location (user 2026-09-30).** Local code at `~/code/jstex`
  (worktrees under `~/code/jstex/.worktrees/`); creating the private GitHub
  repo is authorized, pushing needs confirmation. No `Co-Authored-By`
  trailers in commits.
- **§7.2 — overlapping footprints (user decision 2026-09-30).** Same as STEX:
  a map click on stacked footprints opens a popup listing every item under the
  point (id, date, collection, cloud cover); picking one opens its details.
  Replaces the "click again to cycle" idea. Thumbnails in the popup are
  deferred to a later stage.
- **§7.1 — top bar design (user request 2026-09-30).** Stage 1 includes a
  design pass (plan Task 12) with a user review gate. The top bar has labelled
  groups (Collections · Dates (UTC) · Area of interest · actions) on a grid
  driven by container queries on the widget width, a uniform control height,
  an AOI chip, Clear dates, and a quiet status line for the
  anonymous/no-constraint hints.
- **§7 — layout A, supersedes the vertical top-bar layout and the Task 12 top-bar
  redesign (user decision 2026-09-30, from companion mockups).**
  - A STEX-like search panel (300 px) sits beside the map with the same
    drag-resizable height (default 600 px). Its sections — Collections,
    Dates (UTC), Area of interest, Filters — collapse, scroll inside the panel,
    and show a one-line summary when closed. Search is pinned at the panel
    bottom, with the reason when it is disabled and the sign-in line.
  - The panel collapses to an icon rail with badges and tooltips, only when the
    user clicks ◀; the state is remembered in the `panel_collapsed` trait.
  - Below ~760 px widget width the panel stacks above the map.
  - Results and item details stay below the map at full width.
- **§9 — stage 1 scope grows (user decision 2026-09-30).**
  - Collection search: title/id search, "only selected", and ⓘ with
    description, time extent and license; no tags.
  - Queryables-driven attribute filters: fields shared by all selected
    collections, operators by type, enum dropdowns and inline validation ported
    from STEX.
  - **One** area of interest: polygon or box drawing, GeoJSON upload validated
    in Python (`jstex/aoi.py`) per §4 Workflow B2, zoom-to and remove. There is
    no multi-AOI logic; a new area replaces the old one.
  - These move out of stage 2. Load more, grouped properties, `Explorer(q=…)`,
    S3 and geocoding stay in stage 2.
- **CQL2 operators (verified 2026-09-30).** CDSE answers HTTP 400 to `!=` and
  `IN`, so the UI operators are sent as `<>` and `in`. STEX has the same bug; a
  separate fix task was started.

## 13. Amendments after v0.1.0 (2026-10-01)

- **Stage 2 is split into base and optional (user decision 2026-10-01).**
  - **v0.2 base** (required for `v0.2.0`): Load more (`rel=next`, append
    without duplicates, keep selection); "copy boto3 snippet" per asset;
    `jstex.s3.*` per §6 (opt-in extra); thumbnails in the overlapping-footprints
    popup; geocoding (place search to move the map); bundle-size work (§11);
    the deferred minors from the stage-1 final review.
  - **v0.2 optional** (planned separately, after the base, not blocking
    `v0.2.0`): grouped properties (General / Product / Acquisition / Geometry /
    Storage from STEX `sensor-config.ts`); opening a STEX `q=` link —
    `Explorer(q=<STEX share URL or q value>)` restores the state and
    auto-searches, an invalid `q` shows "Invalid query URL".
  - Stage 2 acceptance criteria in §9 apply per part accordingly.
- **Shipped in v0.1.0 beyond §9 stage 1** (no longer stage 2): attribute
  filters, polygon drawing, GeoJSON upload (§12), date and time (UTC) with
  STEX's calendar, resizable panel, collapsible map.
- **Links.** `ex.query_url()` returns a clickable STAC `GET /search` URL (the
  area falls back to its bbox above 2,000 characters, the CDSE firewall limit);
  the STEX link is `ex.stex_url()` (needs `JSTEX_STEX_URL`). Supersedes the
  `query_url()` wording in §9 stage 2.
- **Package and distribution.** Distribution and labextension
  `jupyterlab-jstex`, import `jstex`; GPL-3.0-or-later; public repo
  `alek-cesarz/jstex`; released on PyPI. Supersedes the private/no-license
  decisions (§2, §12). The opt-in S3 extra is therefore
  `pip install jupyterlab-jstex[s3]`.
- **Basemap.** OpenFreeMap Positron (vector style, no key) in both themes;
  per-theme `JSTEX_BASEMAP_*` for an XYZ template or another style with a key.
  Supersedes the STEX Carto/Stadia basemaps in §7.1 and §12.
- **Profiles, login and S3 keys (2026-10-02).** Designed in
  `2026-10-02-jstex-profiles-auth-design.md` (v0.2 base): profiles merged
  GitHub registry → `eo-services.json` discovery → manual config; token chain
  manual → hub → stored session → device code → password; S3 keys as an own
  port of the STEX policy (no eosdk components yet). Supersedes §6's
  `JSTEX_S3_ENABLED` flag and the fixed CDSE endpoints.
